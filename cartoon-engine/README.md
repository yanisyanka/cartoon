# Cartoon Engine

Учёт и происхождение ассетов мультсериала MOSSKIN.

Движок отвечает на один вопрос про любой файл проекта: **откуда он взялся и
можно ли получить его снова.** Байты остаются на диске там, где лежали, — в базе
живут только адрес, отпечаток и происхождение.

## Установка

```bash
npm install
```

```bash
cp .env.example .env
```

`MEDIA_ROOT` и `DATABASE_URL` обязательны, значений по умолчанию у них нет
намеренно: неверный корень медиа не сломает импорт, а молча зарегистрирует не то
дерево, и обнаружилось бы это гораздо позже.

```bash
npm run db:deploy
```

## Работа

Порядок важен: эталон не регистрируется, пока неизвестно, кто на нём.

```bash
npm run cartoon -- characters import
```

```bash
npm run cartoon -- canon import
```

```bash
npm run cartoon -- assets import --refs
```

Регистрирует все `ref_front.png` из `characters/` с ролью `ref-front` и
привязкой к персонажу. Повторный запуск дубликатов не создаёт: дедупликация идёт
по sha256, а не по пути.

```bash
npm run cartoon -- characters show 01-mossy
```

Персонаж и его текущий эталон: путь, отпечаток, версия, воспроизводимость.

```bash
npm run cartoon -- assets history characters/04-puff/ref_front.png
```

История версий по пути. Перерендер создаёт новую версию; прежняя остаётся
нетронутой, и база не даст её удалить, пока на неё кто-то ссылается.

```bash
npm run check
```

`check:canon` читает десять настоящих паспортов и сверяет их с базой,
`check:assets` снимает отпечатки эталонов до импорта, прогоняет импорт дважды и
пересчитывает отпечатки после. Совпадение — машинное доказательство того, что
регистрация файлы не тронула.

```bash
npm test
```

## Структура

```
cartoon-engine/
  packages/core/src/            ← общее ядро: про мультфильм не знает
    errors.ts                   таксономия ошибок
    media-store.ts              пути, sha256, тип по сигнатуре, канонизация
    provenance.ts               правило назначения происхождения
    asset.ts                    доменные типы, пять исходов импорта
    db.ts                       подключение к базе
    repositories/assets.ts      единственный слой ядра, знающий Prisma
    services/asset-import.ts    регистрация и версионирование

  apps/cartoon/src/             ← предметный слой: духи, канон, роли
    domain/character-md.ts      разбор паспорта
    domain/roles.ts             словарь ролей
    domain/canon-rules.ts       транскрипция правил CAST.md
    repositories/               персонажи и правила
    services/                   импорт персонажей, канона, эталонов
    cli.ts                      команды

  scripts/                      офлайн-проверки
  tests/                        проверки на временной базе и в песочнице
  prisma/                       схема и миграции
  docs/                         решения по задачам
```

Правило слоёв: CLI → services → repositories → Prisma, а физический мир — только
через MediaStore. Абсолютных путей за пределами MediaStore нет.

## Чего здесь сознательно нет

Ни генерации изображений, ни провайдеров, ни роутера, ни учёта стоимости, ни
проверок канона — правила пока только данные. Всё это появится своими задачами,
когда за ними встанет работающий код. Подробности решений — в [docs/](docs/).
