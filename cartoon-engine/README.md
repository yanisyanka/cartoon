# Cartoon Engine

Учёт и происхождение ассетов мультсериала MOSSKIN.

Движок отвечает на один вопрос про любой файл проекта: **откуда он взялся и
можно ли получить его снова.** Байты остаются на диске там, где лежали, — в базе
живут только адрес, отпечаток и происхождение.

## Установка

```bash
npm install
```

```bash
cp .env.example .env
```

`MEDIA_ROOT` и `DATABASE_URL` обязательны, значений по умолчанию у них нет
намеренно: неверный корень медиа не сломает импорт, а молча зарегистрирует не то
дерево, и обнаружилось бы это гораздо позже.

```bash
npm run db:deploy
```

## Работа

```bash
npm run cartoon -- assets import --refs
```

Регистрирует все `ref_front.png` из `characters/`. Повторный запуск дубликатов
не создаёт: дедупликация идёт по sha256, а не по пути.

```bash
npm run cartoon -- assets list
```

```bash
npm run check:assets
```

`check:assets` снимает отпечатки всех эталонов до импорта, прогоняет импорт
дважды и пересчитывает отпечатки после. Совпадение — машинное доказательство
того, что регистрация файлы не тронула.

```bash
npm test
```

## Структура

```
cartoon-engine/
  packages/core/src/
    errors.ts                таксономия ошибок
    media-store.ts           физический слой: пути, sha256, тип по сигнатуре
    provenance.ts            правило назначения происхождения
    asset.ts                 доменные типы
    db.ts                    подключение к базе
    repositories/assets.ts   единственный слой, знающий Prisma
    services/asset-import.ts правила регистрации
  apps/cartoon/src/cli.ts    команды
  scripts/check-assets.ts    офлайн-проверка фундамента
  tests/                     проверки на временной базе и в песочнице
  prisma/                    схема и миграции
  docs/                      решения по задачам
```

Правило слоёв: CLI → services → repositories → Prisma, а физический мир —
только через MediaStore. Абсолютных путей за пределами MediaStore нет.

## Чего здесь сознательно нет

Ни генерации изображений, ни провайдеров, ни роутера, ни учёта стоимости, ни
ролей ассетов и связей между ними. Всё это появится своими задачами, когда за
ними встанет работающий код. Подробности решений — в [docs/](docs/).
